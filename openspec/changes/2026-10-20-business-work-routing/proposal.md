Business coordinates the whole portfolio. Refresh all accessible open issues, reconcile the owner's 20-PR involvement snapshot with the live involved/org queues, and map work to existing implementation owners and P order. Install task-required software when needed, verify capabilities and continue the existing ITIL 5 lifecycle and knowledge records.

## Implementation
Extend the existing research/implementation reconciliation register with a dated overlay rather than creating a competing backlog. Include all 54 public issue routes, retain the two restricted issue routes only in restricted evidence, and cover all 25 current org PRs plus the outside-org involvement item. Keep the user's 20 supplied items distinguishable from newly visible items. Record exact source heads and check/review scope, specific next actions/dependencies and acceptance; label inherited findings when a full new semantic review is incomplete. Add the owner operating preference to the existing agent entry and route navigation to this overlay.

## Boundaries and validation
Business owns portfolio coordination and evidence admission; local runtime/security/legal/release authority remains with its existing owner. Preserve issue histories, standalone research status and normal independent review. Project boards are optional views; no Linear mirror, new tracker stack, authority change or implicit production acceptance. Validate complete unique issue/PR mapping and source hashes; keep restricted findings, credentials, account/customer data and financial strategy out of public changes. The overlay is a reviewable working order, not automatic label changes or a claim that all issues are resolved.
