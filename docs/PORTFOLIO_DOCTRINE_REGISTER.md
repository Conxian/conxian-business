## High-risk contradictions and dispositions

The register records contradictions so they are not silently mistaken for completed external fixes. Upstream repository changes are follow-up work unless explicitly marked as changed in this repository.

| Artifact or surface | Contradiction to resolve | Disposition in this change |
| --- | --- | --- |
| `Conxian/docs/WHITEPAPER.md` | Existing classification and/or narrative may present an outdated protocol, custody, treasury, settlement, or market-position claim as current. | **External follow-up:** reclassify as `Archive candidate (rewrite required)` and rewrite against [TECHNICAL_WHITEPAPER_OUTLINE.md](./TECHNICAL_WHITEPAPER_OUTLINE.md) plus this doctrine. No submodule content was changed here. |
| `Conxian/conxian_market/README.md` | Prototype/documentation language can imply a production settlement core, market capture, or company-controlled fund handling. | **External follow-up:** classify as `Research/experimental` and qualify protocol behavior; no upstream change was made here. |
| `docs/ITIL5_STRATEGIC_ANALYSIS_2026.md` | Competitive/market-capture strategy and sensitive operating analysis are not public-safe. | **Changed here:** replaced with a public-safe stub pointing to the full CON-1530 Linear source; sensitive strategy text is not retained. |
| Top-level READMEs across the portfolio | Role lines and status claims can mix company identity with product/protocol behavior or use stale maturity labels. | **Follow-up by repository:** align each README to this register. The scoped `conxian-business/README.md` is rewritten here; external top-level READMEs are not changed. |
| Company custody, treasury, or signer-control wording | `README.md`, wallet-control, handoff, and signer-verification documents can be read as company custody or discretionary control if protocol/user boundaries are omitted. | **Scoped qualification:** this repository README, Fiscal Vault README, and BOS reference specs now state the boundary. Review remaining governance/control docs separately; no custody procedure is copied here. |
| Protocol escrow, settlement, treasury, or yield descriptions | Contract-level behavior can be mistaken for Conxian-Labs custody or managed-fund operation. | **Scoped qualification:** BOS platform/service-loop/orchestration and Fiscal Vault surfaces now label these as protocol/reference/target-state behavior. Review protocol submodule docs as follow-up. |
| Competitive or market-capture narratives | Dated business analysis, market one-pagers, and upstream whitepaper material can imply that Conxian-Labs operates against or captures markets. | **Follow-up:** preserve only public-safe infrastructure positioning; move sensitive strategy to Linear and classify dated material as internal-only or archive candidate. |
| User-data extraction implications | Product narratives that frame raw data collection, resale, or surveillance as a business purpose conflict with the non-extraction boundary. | **Standing rule:** public docs must describe minimum-necessary integration data and verification, not a data-extraction business. Review affected upstream surfaces as follow-up. |

## Maintenance rule

When a repository, maturity claim, or document classification changes, update this register first, then update explanatory indexes and affected public surfaces. Do not use this register to upgrade evidence; link the evidence that justifies the change.
